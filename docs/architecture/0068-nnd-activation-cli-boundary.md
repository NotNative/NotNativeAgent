# NND activation CLI boundary

Status: candidate preflight and preparation-prefix recovery only. Public activation is not implemented by this decision.

`nna nnd service activation-preflight INSTALL_ROOT STAGE_UUID ACTIVATION_UUID` verifies the selected installed NNA descriptor, obtains the genuine data-root singleton and package-registry mutex, rejects unfinished install or activation evidence, active migration, and unverifiable legacy owners, and reopens the immutable staged candidate. The two UUIDs must be distinct. Its `slot_ready` result binds the selected installation/data identity, payload hash, version, and candidate evidence hash. It does not prepare an activation, switch registration, publish discovery, admit a controller, or imply an installed NND. A failure cannot be turned into success by a cached preflight result.

`nna nnd service activation-preparation-recover INSTALL_ROOT ACTIVATION_UUID` invokes the existing native preparation-prefix reconciler. It can report an absent, prepared, or safely unpublished prefix. It does not reconcile a started trial, selected registration, retired evidence, or a lost retained owner. Those states remain barred and require a later exact-operation recovery command.

The eventual `activate-slot` command must consume both explicit UUIDs in one native owner process. Before mutation, it must revalidate the staged candidate and reject any unmatched pending operation or selected identity. It must hold the singleton lease and registry mutex across preparation, unpublished trial, private discovery, registration selection, held ticket, promoted private attach, retained-owner handoff, completion, retirement plan, external decision, exact cleanup, terminal commit, clearance, native admission transfer, and public-controller attach. Each receipt must match the same operation, stage, generation, installation, data root, package and live child. No later phase may be inferred from a prior witness alone.

The activation process must outlive the invoking CLI client while serving the selected generation. A foreground activation command may remain attached; a background command needs a native supervisor handoff protocol that confirms both process ownership and public attach before reporting success. It cannot return `activated` and exit with the only live service lease. A crash-prefix reconciler must inspect selected pointer, registration, terminal/cleared pair, child process identity and current native gate before deciding whether to resume, stop, or require operator repair. Unknown effects preserve the barrier and return an explicit blocked status. The current retained-owner witness cannot authorize a new process to resume an owner it has lost.

No command here changes NNA TUI behavior or permission governance. Default, Auto-review and Unattended remain NNA-native reviewer modes. The NND installer may consume `slot_ready` only as a preflight result; it may report installation complete only after the later native activation succeeds and authenticated public attach verifies the selected live generation.
