# NND ticket-bound principal confirmation

Status: private same-process prerequisite. No public activation command invokes this confirmation.

The unpublished native listener already stores a one-use principal selection after post-publication health, but continues resolving the trial principal. The private ticket exchange requires that selection. After the durable `private_ticket_verified` receipt is read, the held-live verifier now rechecks health and receipt evidence, then mints a one-use in-memory confirmation for that same listener, trial state, service lease, registry mutex, operation, stage operation, and generation. The native selector consumes it synchronously and compares exact registration revision, publication receipt, generation, operation, and runtime state with the earlier selection. A foreign or replayed proof fails closed. Confirmation never contains the UI ticket, cookie, or controller token.

The confirmed state is only internal evidence. Its selector requires the controller and native listeners to remain live, including when later reading the latch. `resolvePrincipal` continues to return the trial principal; the native admission gate still denies ordinary mutations; controller routes remain dark; the pending marker and activation evidence remain. The final held-live callback still stops the child. A later commit transaction must durably decide completion, promote authority in this same process under the closed gate, transfer supervision and the held lease, retire the terminal barrier safely, and verify public attach before reporting activation. This confirmation alone is not that transaction and cannot survive owner death as authority.
