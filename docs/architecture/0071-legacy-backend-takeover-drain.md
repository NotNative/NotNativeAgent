# ADR 0071: legacy backend takeover drain protocol

Status: accepted. Closes the last L5 mechanism (guide 02, lines 283-291): the first upgrade from the Electron-owned backend whose launcher predates the data-root singleton lock, so the lock cannot exclude it.

The census (`nnd-legacy-census`) already proves exact ownership: every scanned process is classified with native identity evidence (creation-time match via `GetProcessTimes`, never a guessed name or port), and any live legacy `nnd serve` owner or unverifiable process makes adoption fail closed with `nnd_owner_unverified` and no termination. What was missing is the protocol between "an owner exists" and "the new dispatcher may open the same state":

1. Discover. The census run reports, for each legacy owner, the exact pid, creation time, and argv tail, so operators and the installer can name the process being waited for instead of a port guess.
2. Wait for voluntary release. The takeover holds the data-root lease and waits a bounded window (60 s, deadline-abortable) for the legacy owner to exit through its own lifecycle controls — a legacy server that respects the lease releases it, an operator stops the old GUI, or the process ends its in-flight work. The window re-scans on an interval; quiescence is only ever believed with a fresh census whose `legacy` and `unknown` counts are both zero.
3. Never kill. There is no remote graceful stop for a Windows console owner (`nna nnd serve` accepts no subcommand, and termination is not shutdown), so the protocol never sends one. When the window closes with owners still present, activation is refused with `nnd_legacy_takeover_required` naming each observed pid and the exact recovery instructions: exit the legacy desktop/`nna nnd serve` cleanly, then rerun. Independent TUI/headless work is never part of the wait and never terminated.
4. Verify before opening state. Refusal and success alike require the final zero census; absence of a PID or port is never evidence. The existing install-marker/transaction blocks remain the preconditions.
5. Reconcile consumer records before enabling the dispatcher. No legacy outcome is ever replayed and both consumers never run: the session journal is re-verified with resume provenance (`assertResumeProvenance`) before any session becomes resumable, catalog and activity sidecars are validated whole and archived (`0.before`) before rewrite, and live session locks are held through the transaction so a second writer cannot exist. The legacy server's queue and schedule files live in the old NND server's own data directory, which the new dispatcher never opens; because takeover refuses while any owner is live, no record can be half-consumed across the switch, and anything the census still sees is evidence of an owner, not work to adopt. Malformed legacy records fail the migration closed.

The identifier chain holds throughout: the pinned identity and incarnation (ADR 0070) bind which installation is being drained, the census binds which processes own the state, and the migration transaction binds what was reconciled before activation switches registration.
